• Step goals that grow gently from your own recent baseline, with a caution line before you overdo it
• Rest days and flare days never drag down your averages or break a streak
• Resting heart rate and HRV shown next to your own usual, plus a stand test and blood pressure from your cuff

• Export or delete all your data at any time

Available in English, Spanish and Traditional Chinese.

ZebraPace is a self-tracking tool, not a medical device. It does not diagnose or treat any condition and does not replace your doctor, physical therapist or other care providers.

## App content → Health apps declaration (Health Connect permissions)

Review language is English. One justification per permission. All are reads except WRITE_WEIGHT (added in build 6).

**General description of the app's health features**

```
ZebraPace is an energy-pacing and symptom tracker for people with Ehlers-Danlos syndrome, post-exertional malaise (PEM) and dysautonomia, where doing too much on a good day can cause a crash days later. Health Connect data is read only to pre-fill the user's own log and to adjust the user's suggested daily step range. The only data written back is the body weight the user types into the app. It is stored on the device, never sold, never used for advertising, and never sent to third parties. The only exception is user-initiated: if the user joins an optional challenge with friends, that day's total (for example steps or sleep hours) and whether they met their goal are shared with that challenge group.
```

**READ_STEPS**

```
Pre-fills the user's daily step count. Steps drive the core pacing feature: a step goal that grows gently from the user's own recent baseline, with a caution line to help them avoid post-exertional crashes. Also used in step challenges the user chooses to join.
```

**READ_EXERCISE**

```
Shows the workouts recorded today so the user can review them and add them to their activity log (type and duration). Logged activities feed the user's exertion vs. delayed-symptoms insights.
```

**READ_ACTIVE_CALORIES_BURNED**

```
Shows the active energy of each workout the user imports and is used to estimate the workout's METs (intensity), shown in the user's insights and in the PDF summary the user can give their doctor.
```

**READ_TOTAL_CALORIES_BURNED**

```
Health Connect returns a workout's total calories together with the exercise session, and reading workouts fails without this permission. ZebraPace uses it only as part of reading the workouts the user chooses to import.
```

**READ_DISTANCE**

```
Health Connect returns a workout's distance together with the exercise session, and reading workouts fails without this permission. ZebraPace uses it only as part of reading the workouts the user chooses to import.
```

**READ_HEART_RATE**

```
Shows the heart-rate range during each imported workout and during sleep. The user's insights compare how hard a day was (peak heart rate) with how their body felt in the following days, which helps people with PEM recognise their limits.
```

**READ_RESTING_HEART_RATE**

```
Shown in the Autonomic signals card next to the user's own usual (about the last 21 days), so they can notice when their body is recovering less well than usual. It is information only and does not change the step goal.
```

**READ_HEART_RATE_VARIABILITY**

```
Shown in the Autonomic signals card next to the user's own usual (about the last 21 days), so they can notice when their body is recovering less well than usual. It is information only and does not change the step goal.
```

**READ_SLEEP**

```
Pre-fills last night's sleep duration, REM and deep sleep minutes, and sleeping heart rate in the user's sleep log, which feeds their daily energy estimate. The user reviews the values before saving.
```

**WRITE_WEIGHT**

```
When the user types their body weight into ZebraPace, it is saved to Health Connect so their other health apps see it too. Only that weight is written. Correcting a day's weight replaces the record ZebraPace wrote for that day; records from scales or other apps are never changed or deleted.
```

**READ_HEALTH_DATA_IN_BACKGROUND** (added in build 9)

```
Used only for optional pacing alerts, which the user turns on in Settings. About every 15 minutes while the app is closed, ZebraPace reads today's step total and compares it with the user's own step goal and caution line. It then notifies the user, at most once each a day, when they reach the goal or pass the caution line, so they can stop before overexertion leads to a post-exertional crash. Only today's step total is read in the background; nothing is written and nothing leaves the device. Turning the alert off stops the background reads.
```

## App content → Data safety (answers)

- Does your app collect or share any of the required user data types? **Yes**
- Is all collected data encrypted in transit? **Yes**
- Do you provide a way for users to request that their data is deleted? **Yes** — URL: https://zebras.paulinavl.com/delete-account/ (deploy zebra-site first)

Data types (all: Collected = yes, Shared = no, processed ephemerally = no):

| Data type | Required or optional | Purpose |
|---|---|---|
| Personal info → Email address | Optional | Account management |
| Personal info → Name (display name in challenges) | Optional | App functionality |
| Health and fitness → Health info (weight in weight challenges; rest/flare days) | Optional | App functionality |
| Health and fitness → Fitness info (daily challenge values: steps, sleep hours, active minutes) | Optional | App functionality |
| Location → Approximate location (the place typed for weather, sent to Open-Meteo without account or health data) | Optional | App functionality |
| App info and performance → Crash logs | Required | Analytics |

Not collected: the health log itself (it stays on the device) and Health Connect data other than the challenge totals above.

"Shared = no": Supabase, Resend and Open-Meteo process data on our behalf (service providers), and challenge values go to the group only because the user joins it (a user-initiated transfer the user expects). Play counts neither as sharing.

Deletion: tick both "in-app" and "request via URL".
